# Scrolly — Engineering Status

Last updated after the UI / correctness / testability pass.

## Build & test

```bash
./gradlew :app:assembleDebug        # APK
./gradlew :app:testDebugUnitTest    # unit tests
./gradlew :app:lintDebug            # static analysis
```

`bt.bat` is a thin wrapper that pins `JAVA_HOME` to the JDK 21 installed locally.

### Toolchain notes

- **JDK 21** is required (AGP 9.1). `gradle/gradle-daemon-jvm.properties` was **deleted**:
  it is generated by Android Studio and pinned the daemon to JDK 25, so any machine or CI
  runner without that exact JDK build failed during configuration. It is now gitignored.
- The Gradle wrapper (`gradlew`, `gradlew.bat`, `gradle-wrapper.jar`) was restored. It was
  missing, so the project could not be built by anything except a machine that happened to
  have a matching Gradle installed.
- `testOptions` sets `forkEvery = 1`: Robolectric can initialise its native graphics runtime
  only once per JVM, so the Roborazzi screenshot test collided with the rest of the suite
  (`FileSystemAlreadyExistsException`) unless each class gets its own fork.

## Database

- `app_stats` moved from a surrogate `id` primary key to the natural
  `(date, packageName)` key. v2 permitted two rows for the same app/day, which is why the
  repository previously needed a read-modify-write on every scroll.
- **Version 2 → 3** with an explicit `MIGRATION_2_3` that sums duplicate rows instead of
  dropping them. `fallbackToDestructiveMigration()` was removed: it would have silently
  erased a user's entire scroll history on upgrade.
- Room schema JSON is now exported to `app/schemas/` and committed, so future migrations
  have a reviewable baseline. `2.json` was authored by hand because it predated export.
- First-run seeding now runs through raw SQL on the `SupportSQLiteDatabase` Room supplies.
  The previous coroutine-based version raced with the `INSTANCE` assignment and could
  silently no-op, leaving a fresh install with no limits, achievements or battles.

## Correctness fixes

| Area | Problem | Fix |
|---|---|---|
| `TrackingRepository` | Captured `today` once in `init`, so after midnight the counter kept climbing from yesterday's total | `trackedDate` + a 60s rollover watcher; observers re-subscribe via `flatMapLatest` |
| `TrackingRepository` | Only ever accepted *increases* from the database, so one failed write left the counter permanently inflated | Memory is recomputed as `storedTotal + pendingDelta` and re-anchored after every write |
| `TrackingRepository` | "Limit reached" block persisted forever across days | `clearAllBlocks()` on rollover |
| `TrackingRepository` | Challenge bonus was **added to and persisted in** `dailyLimit`, so five claims multiplied the user's own ceiling | Bonuses live in a session-only map, cleared on rollover |
| `TrackingRepository` | 4 separate non-transactional DAO calls per scroll | Single `recordScrollAtomic` transaction |
| `ScrollyDatabase` | `endOfDayMillis(date)` ignored `date` and always returned the start of the next *real* day, so querying a past day returned a two-day window | Derived from the parsed date. Found by a new test. |
| `ScrollDetectionEngine` | Comment-sheet detection matched `className.contains("comment")`, which also matches Instagram's normal Reel comment button — it would silently stop **all** reel counting | Restricted to sheet-specific view IDs / class names |
| `ScrollDetectionEngine` | Rejected `scrollDeltaY < 0`, discarding most real reel swipes (sign convention varies by OEM) | Classified by magnitude |
| `ScrollDetectionEngine` | `resetState()` could emit the hide callback twice | Single emission |
| `NotchFloatingBarManager` | `keepAttached` was accepted and ignored; `hide()` never detached when the animation controller was null (leaked a live overlay) | Flag honoured; direct cleanup fallback |
| `NotchFloatingBarManager` | `BELOW_NOTCH` used the raw `offsetY` whenever it was > 0, bypassing the safe inset — since auto-calibration always produced a positive offset, the pill could sit under a tall status bar | Clamped to the hardware safe inset |
| `FirebaseManager` | `FirebaseAuth.getInstance()` was called from an unguarded getter; `ProfileViewModel.getMyUid()` therefore crashed on any build without `google-services.json` | Every accessor is fail-soft |
| `FirebaseManager` | Friend list issued `1 + N` sequential document reads | Chunked concurrent reads |
| `ScrollyApp` | `GlobalScope.launch` leaked a Job for the process lifetime | Application-scoped coroutine |
| `ProfileScreen` / `BattlesScreen` / `StatsScreen` | Displayed hardcoded data (14,832 scrolls, 11-day streak, 23W/17L, a 36-vs-93 matchup) | All derived from the database |
| `StatsViewModel` | Morning/Afternoon/Evening/Night split was a fixed 15/35/40% ratio of the day's total, unrelated to real activity | Bucketed from the raw event log |
| `HomeScreen` | "N left" used `(1f - fraction) * goal`, so 100 of 100 read "1 left" | `goal - total` |
| `BlockScreen` | "Emergency Override" was a `Text` styled to look like a button that did nothing | Real button granting a session bonus |
| `BlockScreen` | Challenge "Claim" could be pressed unlimited times | Disabled once claimed |
| `BlockScreen` | Slider wrote to the database on every pixel of drag | Committed on release only |

## UI changes

- Palette rebalanced. The old values were Material 3's baseline light scheme copied
  verbatim: background and card surface were ~4 values apart, so cards had no visible
  edge, and `0xFFCAC4D0` borders fell below the 3:1 non-text contrast WCAG requires.
- The Dynamic Island preview and notch customiser no longer use hard-coded dark hexes
  (`0xFF141A22`, `Color.Black`) that clashed with the light theme.
- "Active Apps" moved from a fixed five-across `Row` (which ellipsised labels on narrow
  phones) to a wrapping grid.
- Only the visible tab's ViewModel is created; previously all five were instantiated up
  front, so every screen's repository flows ran even when its tab was never opened.
- Empty states, `contentDescription`s and a real "sign in to invite" explanation added.

### Known limitation

Dark mode is **not** implemented. Every screen paints with explicit palette tokens rather
than `MaterialTheme.colorScheme`, so wiring a dark scheme into `MaterialTheme` alone would
theme a handful of components and leave the rest bright white — which reads as a bug. It
needs the tokens to become theme-aware first (a `CompositionLocal` palette touching ~445
call sites).

## Tests

98 unit tests, all passing. Up from 6 — three of which were placeholders, one of them
`2 + 2 == 4`.

| Suite | Tests | Covers |
|---|---|---|
| `TrackingRepositoryTest` | 29 | Atomic writes, rollover + listeners, limits, bonuses, aggregates (real in-memory Room) |
| `DerivedStatsTest` | 23 | Streaks, levels, time-of-day bucketing, day boundaries |
| `ScrollDetectionEngineTest` | 20 | Package filtering, feed entry/exit, carousel rejection, comment sheet |
| `AppRecognitionAndCutoutTest` | 13 | App-name resolution, notch classification, date arithmetic |
| `ScrollyDatabaseMigrationTest` | 7 | v2→v3 migration against a real v2-schema database |
| `NotchAndAppSetupTest` | 5 | Notch settings, stats navigation |
| `DynamicIslandScreenshotTest` | 1 | Roborazzi snapshot |

Two of these tests caught real bugs during the pass:

- `endOfDayMillis(date)` ignored its argument and returned the start of the next *real*
  day, so querying a past day returned a two-day window that leaked today's events.
- The comment-sheet guard matched `className.contains("comment")`, which also matches
  Instagram's ordinary Reel comment button.

Migration tests drive the migration SQL directly instead of using `MigrationTestHelper`:
AGP 9 exposes no unit-test asset-merging task, so Robolectric cannot see the exported
schema JSON.

## Repository hygiene

- Removed `scrolly.apk` (27.4 MB) and `public/app-debug.apk` from version control;
  `*.apk`, `*.aab`, `*.jks` are now gitignored.
- Added `.github/workflows/ci.yml` (compile → test → lint → assemble on JDK 21).
- `lintDebug` is clean. It previously failed on a real `NewApi` error:
  `NotchDetectionHelper.parseDisplayCutout` passed a `DisplayCutout` (API 28) through an
  unguarded facade, which would have thrown on API 24–27 devices.

## Follow-ups

1. Theme-aware colour tokens, then dark mode.
2. String resources — all UI copy is still hardcoded in Kotlin, which blocks localisation.
3. `isMinifyEnabled` is still `false` for release; turn on R8 with a keep-rules pass once
   the Firebase/Room reflection surfaces are verified on a release build.
4. `POST_NOTIFICATIONS` is declared but never requested, and no notification is posted.
5. `limitReachedEvents` is emitted by `TrackingRepository` but nothing observes it, so the
   block intervention is currently only previewable from the Block tab.
